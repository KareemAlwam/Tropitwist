# Tropitwist Hosted Deployment

This is the low-cost deployment path for the first six months: Cloudflare Pages
for the storefront, Render for the Express API, and Neon for PostgreSQL. The
repository is already configured for it with `render.yaml` and `public/_redirects`.

Keep the domain registered with Hostinger. Moving its nameservers to Cloudflare
later changes only DNS management, not domain ownership or renewal.

## 1. Create the Neon Database

1. Create a Neon project in a region close to Egypt, preferably Frankfurt.
2. Copy the pooled PostgreSQL connection string from Neon. Do not paste it in
   GitHub, chat, or any committed file.
3. Keep the Neon project on its free plan for the current test phase.

The API applies its own PostgreSQL migrations when it starts. No manual SQL is
required for the first deployment.

## 2. Deploy the API on Render Free

1. In Render, choose **New** -> **Blueprint** and connect this GitHub repository.
2. Render reads `render.yaml`. Leave the plan as **Free** for now.
3. During setup, provide these environment values:

```dotenv
DATABASE_URL=<Neon pooled connection string>
FRONTEND_ORIGIN=https://tropitwist.store,https://www.tropitwist.store
ADMIN_EMAILS=<your admin email address>
PAYMOB_SECRET_KEY=
PAYMOB_PUBLIC_KEY=
PAYMOB_CARD_INTEGRATION_ID=
PAYMOB_HMAC_SECRET=
PAYMOB_WEBHOOK_URL=
PAYMOB_REDIRECT_URL=
```

`JWT_ACCESS_SECRET` is generated by Render. Leave all Paymob values blank until
the merchant account supplies test credentials. Render provides an API URL such
as `https://tropitwist-api.onrender.com`; verify this first:

```bash
curl -fsS https://<render-service>.onrender.com/api/v1/health
```

The Free service sleeps after 15 minutes of no traffic. Use it only for a
staging/demo deployment. Before real customers, paid orders, or investor demos,
change the Render service's compute plan to Starter in its dashboard. The code
and environment variables remain unchanged.

## 3. Deploy the Storefront on Cloudflare Pages

1. In Cloudflare, open **Workers & Pages** -> **Create application** -> **Pages**.
2. Connect the GitHub repository.
3. Use these build settings:

```text
Framework preset: Vite
Build command: npm run build
Build output directory: dist
Root directory: leave empty (repository root)
```

4. Add this production environment variable before the first production build:

```dotenv
VITE_API_BASE_URL=https://api.tropitwist.store
```

Cloudflare Pages redeploys the storefront automatically after each push to
`main`. The `_redirects` file makes direct links such as `/checkout` and
`/products/p1` load the React application correctly.

## 4. Connect the Domain and API Subdomain

Use the custom domain names below. They keep the API and storefront on the same
site, so the secure refresh-token cookie works reliably.

```text
https://tropitwist.store       storefront
https://www.tropitwist.store   storefront alias
https://api.tropitwist.store   Express API
```

1. Add `tropitwist.store` and `www.tropitwist.store` as custom domains in the
   Cloudflare Pages project.
2. In Hostinger, change the domain's nameservers to the two Cloudflare values
   shown in the Cloudflare dashboard. The domain remains registered at Hostinger.
3. In Render, add `api.tropitwist.store` as the API service custom domain.
4. Create the DNS record Render requests in Cloudflare DNS, normally a CNAME
   for `api`. Leave it **DNS only** until Render verifies its certificate.
5. Confirm `https://api.tropitwist.store/api/v1/health` responds successfully.
6. Trigger a new Cloudflare Pages deployment after `VITE_API_BASE_URL` is set.

## 5. Enable Paymob Later

After the custom API domain is working, configure Paymob with:

```dotenv
PAYMOB_WEBHOOK_URL=https://api.tropitwist.store/api/v1/payments/paymob/webhook
PAYMOB_REDIRECT_URL=https://tropitwist.store/checkout
```

Add the remaining Paymob credentials in Render's environment settings. Never
put them in `render.yaml`, `.env.example`, or GitHub Actions variables.

## 6. Production Smoke Test

- Load the custom storefront domain and confirm products load.
- Register a customer, reload, and confirm the session remains active.
- Add items as a guest, sign in, and confirm the cart is retained.
- Place one cash-on-delivery order and confirm it appears in customer and admin
  dashboards.
- Confirm the API health URL works and review Render logs for errors.
- Test Paymob only with test credentials before enabling live card payments.

## Costs and Upgrade Point

Cloudflare Pages and Neon can remain on their free plans for early validation.
Render Free is appropriate for testing only because of its idle sleep. Upgrade
only the Render API to its paid Starter plan when the store is ready for real
visitors. Upgrade Neon when its free storage, compute, backup, or reliability
limits become a constraint.
